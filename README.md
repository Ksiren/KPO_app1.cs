# KPO_app1.cs

	SOLID:

[S]ingle Responsibility Principle (Принцип единственной ответственности):
Классы животных и вещей - отвечают только за хранение своих данных
Zoo - отвечает только за управление листом животных и хранение его
VetClinic - отвечает только за проверку здоровья
ReportMaker - создание отчетов

[O]pen-Closed Principle (Принцип открытости/закрытости) - 

[L]iskov Substitution Principle (Принцип подстановки Барбары Лисков):
Все классы животных и вещей могут быть использованы вместо их базового класса без изменения корректности программы. 
(Как Zoo работает с Animal и Thing, не зная о конкретных типах)

[I]nterface Segregation Principle (Принцип разделения интерфейса):
У каждого интерфейса свои свойства
IAlive - Только свойство Food
IInventory - Только свойство Number
IHealthCheck - Только свойство HealthyCheck

[D]ependency Inversion Principle (Принцип инверсии зависимостей):
Zoo не зависит от конкретной реализации VetClinic. Он зависит от абстракции — интерфейса IHealthCheck.
Program не создает зависимости напрямую, за это отвечает DI-контейнер, который собирает все части приложения воедино.
